# polysted 機能目録

STED2（X68000 の MIDI シーケンサ）の入力方式とデータ構造を Clojure で再現したエディタの、**機能ごとの目録**です。2026-11-19 時点（コミット `4492db6` の次）の実装をもとにしています。

## この目録の使い方

| 目的 | 見るところ |
|---|---|
| 1 機能ずつの学習チュートリアル（note 記事・webcircus の `/content/md/`）の章立て材料 | 各機能の「章立ての案」と、最後の [連載の章立て案](#7-連載の章立て案) |
| 機能チェック（動くかどうかの確認） | 各機能の「操作」と「確認」 |
| 追加・改善のバージョン検討 | 各機能の「改善・拡張の候補」と [未実装・未確認](#6-未実装未確認残件) |
| Clojure 学習の土台 | 各機能の「Clojure の学習ポイント」と [Clojure の学習索引](#4-clojure-の学習索引) |
| 変更・改造のときの地図 | [全体の地図](#1-全体の地図)、各機能の「実装の場所」、[改造の地図](#5-改造の地図) |

各機能の項目は次の並びです。

- **できること** — 1〜2 行の説明
- **操作** — TUI（端末）/ GUI（ウィンドウ）/ REPL（`s/` は `polysted.session` の別名）
- **実装の場所** — ファイル → 主な関数（`file:関数` で検索できます）
- **原作の根拠** — STED2 のソース（[cat2151/STed2.07m](https://github.com/cat2151/STed2.07m)）のファイル・関数、またはマニュアル・資料
- **設計判断** — 原作と違うところ、推測で決めたところ（詳しくは `実装状況と仕様.md`）
- **確認** — 簡易チェック（各名前空間の `run-checks`、`clojure -M:check` で全部）など
- **Clojure の学習ポイント** — その実装で使っている言語機能・書き方
- **章立ての案** — チュートリアルにするときの小見出しの候補
- **改善・拡張の候補**

## 1. 全体の地図

### 1.1 層の構成

```
            ┌──────────── UI 層 (入力の変換と描画だけ) ────────────┐
            │  REPL (s/xxx)        TUI (端末)          GUI (Swing)    │
            │  polysted.session    polysted.tui-base   polysted.gui   │
            │  の短い関数          polysted.tui-screens (TUI の画面と │
            │  dev/user.clj        polysted.tui         キー処理を共有)│
            └──────────────────────┬──────────────────────────────┘
                                   │ dispatch / commands 表、view
            ┌──────────── セッション (状態 + undo) ────────────┐
            │  polysted.session: (state, 引数…) → state の編集コマンド、│
            │  再生・録音・ファイル入出力 (副作用はここに集める)       │
            └──────────────────────┬──────────────────────────────┘
                                   │
            ┌──────────── 純粋関数のコア (レコード列 → レコード列) ────────────┐
            │ polysted.mml (MML・SMF 書き出し)  polysted.rcp (RCP/R36/G36)       │
            │ polysted.edit (編集)  polysted.notename  polysted.edn  polysted.smf │
            │ polysted.replace  polysted.rhythm  polysted.ctrl  polysted.roll     │
            │ polysted.visual  polysted.score  polysted.record                    │
            └─────────────────────────────────────────────────────────────────┘
```

- **データの正体**: 1 トラック = 4 バイトのレコード `[b0 b1 b2 b3]` のベクタ。音符は `[キー ST GT ベロシティ]`、0x80 以上はコマンド。曲は EDN（Clojure のマップ）。
- **純粋関数のコア**: ほとんどの機能は「レコード列を受け取って新しいレコード列を返す」関数。テストしやすく、REPL で試しやすい。
- **副作用**（ファイル・再生・録音・端末・ウィンドウ）は `src/polysted/session.clj` の `!` の付いた関数と、`src/polysted/tui.clj` の `perform`・`run!`、`src/polysted/gui.clj` に集めている。

## 2. 機能目録

### 第 1 部 データとファイル

#### F01 4 バイトレコードと曲のデータモデル
- **できること**: 曲 = `{:title :tempo :timebase :time-sig :key … :tracks [{:recs [[b0 b1 b2 b3] …] :ch :mute? …}]}`。音符 `[キー ST GT VEL]`、休符は GT か VEL が 0、和音は ST=0 の音を続ける、タイは GT > ST。
- **操作**: REPL `(s/show)`、TUI の編集画面（MEAS STEP NOTE K# ST GT VEL の表）。
- **実装の場所**: `src/polysted/session.clj` `new-song`・`new-session`・`table-view`、`src/polysted/rcp.clj` `decode-record`（レコード → イベントの意味）。
- **原作の根拠**: RCP 形式の 4 バイトレコード、TRACK.C・EDITS.C（コマンドコード、`meas_no`・`meas_add`）。
- **確認**: `polysted.session` の「表示」系のチェック。
- **Clojure の学習ポイント**: ベクタとマップだけでデータを表す、分配束縛 `[[a b c d]]`、不変データの更新 `assoc-in`・`update-in`。
- **章立ての案**: ① なぜ 4 バイトか（休符もタイも専用コードが無い）② 曲をマップで表す ③ REPL で 1 音を作って表示する。
- **改善・拡張の候補**: レコードを型（record / spec）で検査する、説明付きの表示（`describe`）。

#### F02 MML 入力
- **できること**: `l8 cdefg <c` のような MML を 4 バイトレコードにして挿入。長さ・オクターブは直前のノートから引き継ぐ。
- **操作**: TUI `m`、REPL `(s/mml "l8 cdefg")`。
- **実装の場所**: `src/polysted/mml.clj` `parse-mml`、`src/polysted/session.clj` `insert-mml`・`mml-defaults`・`key-at`。
- **原作の根拠**: KEY_SUB.C の `mml_inp`（エディット画面の MML 入力）と `scale_no`（調）【確認】。臨時記号が文字列の先頭（`*s`）を見る原作の癖はまねない【設計判断】。
- **確認**: `polysted.session`「MML を挿入するとカーソルが進む」ほか。
- **Clojure の学習ポイント**: 文字列のパース（正規表現 `re-seq`・`re-find`）、`loop`/`recur` による状態つき走査。
- **章立ての案**: ① MML の文法 ② トークンに分ける ③ 長さとオクターブを状態として持つ ④ レコードに変換。
- **改善・拡張の候補**: 和音記法、タイ記号、エラー位置の表示。

#### F03 音名入力
- **できること**: `C4 E G C5`、`Bb5`、`C<`、キー番号 `60` などを解釈。オクターブ省略は直前の音から、調号は曲の調から。
- **操作**: TUI `n`（`Enter`）、直接入力の K# 欄、REPL `(s/n "C4 E G")`。
- **実装の場所**: `src/polysted/notename.clj` `parse-token`・`parse-notes`、`src/polysted/session.clj` `insert-notes`・`key-at`（調）。
- **原作の根拠**: KEY_SUB.C の `ctc`（音名・臨時記号・オクターブ・調号の取り消し）と STDEF.C の `str_val`（数値）【確認】。`Cb` と、知らない文字の扱いだけ独自【設計判断】。
- **確認**: `polysted.notename` 24 件（原作を手で追ったもの 4 件を含む）。
- **Clojure の学習ポイント**: 小さな純粋関数の組み合わせ、`cond` の分岐、マップで文脈（直前のキー・調）を渡す。
- **章立ての案**: ① 音名 → キー番号 ② オクターブの省略と相対記号 ③ 調号の適用 ④ エラーの扱い。
- **改善・拡張の候補**: 長さ付きの音名（`C4:8` など）、入力中の候補表示。

#### F04 RCP / R36 の読み込みと書き出し
- **できること**: レコンポーザ v2 形式（18 / 36 トラック）を読み、編集してそのまま書き戻す。メモ・リズム割り当て・ユーザーエクスクルーシブなどの見出しの項目も保つ。
- **操作**: TUI `w`（拡張子 `.rcp` / `.r36`）、起動 `clojure -M:tui x.rcp`、REPL `(s/open! "x.rcp")`・`(s/save-rcp! "x.rcp")`。
- **実装の場所**: `src/polysted/rcp.clj` `read-rcp`・`read-track`・`write-rcp!`・`song->rcp-bytes`・`normalize-track-records`（`dclr`・`same_cluc` 相当）。
- **原作の根拠**: FILE.C `dload`・`dsave`・`hedread`・`hedset`・`thedset`。
- **設計判断**: 文字列欄は最初の 0x00 で切る、小節線の番号は保存時に `[FD 1 0 0]`。
- **確認**: サンプル 4 つで「RCP → EDN → RCP」のバイト一致（品質の整備のときに確認）。
- **Clojure の学習ポイント**: Java のバイト配列（`byte-array`・`aget`・符号なしへの変換 `bit-and 0xFF`）、`java.nio.file.Files`、Shift-JIS（`Charset`）。
- **章立ての案**: ① ファイルの見出しを読む ② トラックの見出しとレコード ③ 書き戻しで元に戻るか ④ 往復テスト。
- **改善・拡張の候補**: 壊れたファイルの診断表示、MCP 形式。

#### F05 RCP v3（G36）の読み込み
- **できること**: レコンポーザ 3.0 の .G36（6 バイトレコード、ST・GT が 16 ビット）を、STED2 の 4 バイトの形に変換して読む。
- **操作**: `s/open!`、`clojure -M:tui x.g36`、GUI の「開く」（形式は見出しで判定）。
- **実装の場所**: `src/polysted/rcp.clj` `g36-bytes?`・`read-g36-bytes`・`g36-records`、`src/polysted/session.clj` `song-from-rcp`。
- **原作の根拠**: STED2 は G36 を読まない。形式は rcm2smf（shingo45endo 氏、MIT）の `rcm_converter.js`【資料】。
- **設計判断**: ST > 255 は休符で分ける、GT > 255 は 255、コメント・エクスクルーシブは 2 バイトずつに詰め直す。トラックの種類の bit7 がリズムなのは Valley Bell 氏の `RCPFormat.txt` で確認。
- **確認**: 組み立てた G36 のバイト列のチェック（`polysted.session`）、rcp2mid-web-public の合成サンプル（見出し・メモ・音符・SMF・RCP の往復）。**レコンポーザで作った実際の曲では未確認（残件）**。
- **Clojure の学習ポイント**: 16 / 32 ビットのリトルエンディアン、`atom` で警告を数える、`cond->` で警告の一覧を作る。
- **章立ての案**: ① v2 と v3 の違い ② 6 バイト → 4 バイト ③ 収まらない値の扱い ④ 外部資料を根拠にするときの書き方。
- **改善・拡張の候補**: 実データでの確認、G36 の書き出し。

#### F06 SMF（.mid）の読み込みと書き出し
- **できること**: SMF を読んでチャンネルごとのトラックにする（SysEx はトラックエクスクルーシブに）。曲を SMF に書き出す（ST+・K#+・エクスクルーシブを反映）。
- **操作**: `s/open! "x.mid"`、`(s/save-mid! "x.mid")`、TUI `w` で `.mid`。
- **実装の場所**: `src/polysted/smf.clj` `read-smf`・`sequence->song`・`exclusive-records`、`src/polysted/mml.clj` `->sequence`・`write-mid!`、`src/polysted/rcp.clj` `records->events-ex`。
- **原作の根拠**: 原作の演奏は常駐ドライバ RCD。SMF 変換は独自【設計判断】、エクスクルーシブの特殊コード（gt ve ch cs ss）はマニュアル【確認】。
- **確認**: `polysted.smf` 8 件、エクスクルーシブの SMF 往復のチェック。
- **Clojure の学習ポイント**: `javax.sound.midi` の Java 相互運用（`Sequence`・`MidiEvent`・`ShortMessage`）、`doseq` の `:let`・`:when`。
- **章立ての案**: ① 相対時刻 → 絶対時刻 ② MIDI メッセージを作る ③ 読み込みでのチャンネル分け ④ SysEx。
- **改善・拡張の候補**: SMF フォーマット 0 / 1 の選択、テンポマップの扱いの改善。

#### F07 EDN での保存・読み込み
- **できること**: 曲を Clojure のデータ（EDN テキスト）として保存・読み込み。保存形式の正。
- **操作**: TUI `w`（`.edn`）、REPL `(s/save! "x.edn")`・`(s/load! "x.edn")`。
- **実装の場所**: `src/polysted/edn.clj` `save-song!`・`load-song`。
- **確認**: `polysted.edn` 7 件。
- **Clojure の学習ポイント**: `pr-str`・`clojure.edn/read-string`、データ = ファイル形式。
- **章立ての案**: ① EDN とは ② 保存と読み込み ③ 差分が見やすい書き方。
- **改善・拡張の候補**: 版番号を入れる、git で差分を見やすい整形。

#### F08 再生（全体・ポイントプレイ・小節プレイ）
- **できること**: Java のシーケンサで演奏。カーソルの小節から（ポイントプレイ）、カーソルの小節だけ（小節プレイ）。ST+・K#+・エクスクルーシブも反映。
- **操作**: TUI `p` / `Space`（再生・停止）、`P`（カーソルの小節から）、`Ctrl-X mplay`、GUI `F12`、REPL `(s/play!)`・`(s/stop!)`。
- **実装の場所**: `src/polysted/session.clj` `play!`・`play-here!`・`play-measure!`・`measure-tick`・`measure-span`・`new-sequencer`・`synth-receiver`（内蔵音源を遅れ 40ms で 1 度だけ開いて共有）、`src/polysted/mml.clj` `->sequence`。
- **原作の根拠**: マニュアル（テンポ 0xE7 の換算、ST+・K#+、ポイントプレイ・小節プレイ）、EDITS.C `poplay`。
- **設計判断**: GRADATION（テンポの変化の速さ）は瞬時に変える、PLAYBIAS は使わない。内蔵音源の遅れは 40ms（Java の既定は 120ms。`polysted.latency` で変更）。
- **確認**: 再生用の変換のチェック。音は人の耳で確認。
- **Clojure の学習ポイント**: `defonce` の `atom` で再生中のシーケンサを持つ、`future` で終わりを見張る、`reify` で Java のインターフェース（`MetaEventListener`）。
- **章立ての案**: ① シーケンスを作る ② 再生と停止 ③ 途中から再生 ④ 1 小節だけ再生（ほかのトラックのミュート）。
- **改善・拡張の候補**: 再生位置の表示（カーソルの追従）、GRADATION の再現。

### 第 2 部 編集の基本

#### F09 カーソル・挿入・削除・undo / redo
- **できること**: 行の移動、トラックの切り替え（同じ時刻へ）、レコードの挿入・削除、100 回までの undo / redo。
- **操作**: TUI `↑↓` `←→` `x` `u` `Ctrl-R`、REPL `s/go` `s/mv` `s/trk` `s/del` `s/ins` `s/un` `s/re`。
- **実装の場所**: `src/polysted/session.clj` `push-undo`・`undo`・`redo`・`insert-recs`・`delete-recs`・`select-track-at`・`commands`・`dispatch`。
- **確認**: `polysted.session`「削除と undo」ほか。
- **Clojure の学習ポイント**: 不変データだから undo はスナップショットを積むだけ、`(state, 引数) → state` の設計、コマンド表（キーワード → 関数）と `apply`。

- **できること**: ドラッグで高さ・時刻・長さ、ダブルクリックで追加、右クリックで削除（グリッドに合わせる）。

- **章立ての案**: ① 相対時間のデータを絶対時間で編集する難しさ ② 置く・消す・動かすの規則 ③ マウスの操作と undo。

#### F36 コントローラのビジュアルエディット
- **できること**: ボリューム・ピッチベンドなどの変化をグラフでなぞって作る。F キーの波形、ステップの加工、試し再生、縦の拡大、トラックエクスクルーシブにも。

### 第 7 部 録音と環境

#### F39 レコーディング
- **できること**: MODE が Mix・Rec のトラックへ MIDI 入力を録音（メトロノーム、2 小節のカウント、THRU）。
- **操作**: `Ctrl-X rec`、GUI「再生 → レコーディング」。MIDI キーボードが無ければ `clojure -M:vmidikey:tui` で仮想 MIDI キーボード VMidiKey を入力の機器に（README）。
- **実装の場所**: `src/polysted/record.clj` `midi->records`・`apply-recording`、`src/polysted/session.clj` `record-start!`・`record-stop!`・`record-event!`・`midi-inputs`・`rec-tracks`、`src/polysted/tui_screens.clj` `rc-key`・`render-record`。
- **原作の根拠**: RECORD.C `real_record`・`proc_next`・`flash`・`ent_dat`・`proc_excl`・`rec_ext`。
- **設計判断**: アフタータッチの対応を VISUAL.C に合わせる、長い音はつなぎの音だけ、フィルタ・外部同期は未実装。
- **確認**: `polysted.record` 4 件、入力を直接与えた録音、仮想 MIDI キーボード [VMidiKey](https://github.com/CountZeroNM/vmidikey)（別プロジェクト）の機器経由の録音。**実機（MIDI キーボード）では未確認（残件）**。
- **Clojure の学習ポイント**: Java の `Receiver` を `reify` で実装、別スレッドからの記録を `atom` に貯める、時刻付きイベント → レコードの変換。
- **章立ての案**: ① MIDI 入力を受ける ② 時刻を付ける ③ レコードに変換 ④ トラックへ書き込む（置き換え / 混ぜる）。

#### F40 TUI の端末層
- **できること**: raw モードの端末で全画面描画、キーの解読（矢印・F キー・Alt・Ctrl）、端末の大きさの追従。
- **操作**: `clojure -M:tui [file]`、REPL `(s/tui)`。
- **実装の場所**: `src/polysted/tui_base.clj` `decode-keys`・`char-width`・`cut-width`、`src/polysted/tui.clj` `run!`・`read-keys`・`draw!`・`perform`。
- **確認**: `polysted.tui` 90 件、Python の疑似端末（pty）でキーを送って画面を確認。
- **Clojure の学習ポイント**: 純粋な `handle-key`（ui, key → ui）と副作用の `:effects` を分ける設計、全角文字の幅。
- **章立ての案**: ① エスケープシーケンス ② 純粋なキー処理と副作用の分離 ③ 描画 ④ pty でのテスト。

#### F41 REPL の起動
- **できること**: 全部の名前空間を読み込み、`s` を `polysted.session` の別名にして REPL を開く。TUI・GUI・チェックを 1 つのコマンドで起動する。
- **操作**: `clojure -M:repl`（rebel-readline）、`clojure -M:dev`、`bb repl.bb`（`--plain`）、`clojure -M:tui [file]`、`clojure -M:gui [file]`、`clojure -M:check`。
- **実装の場所**: `dev/user.clj`、`deps.edn`（`:paths ["src"]` とエイリアス）、`repl.bb`、`polysted.tui/-main`・`polysted.gui/-main`・`polysted.session/open-at-start!`、`polysted.check`。
- **Clojure の学習ポイント**: `src/` とファイル名・名前空間の対応（`-` ↔ `_`）、`:require` と `requiring-resolve`、`user.clj` が自動で読まれる仕組み、`deps.edn` の `:paths`・`:extra-paths`・`:main-opts`（`-m` と `-main`）、babashka の `babashka.process`。

## 5. 改造の地図

### 5.1 新しい編集コマンドを足す
1. 純粋関数を書く（レコード列の操作なら `src/polysted/edit.clj`、ほかは役割に合うファイル）。期待値を手で求めたチェックを `run-checks` に足す。
2. セッションの関数 `(defn foo [s …] (-> s push-undo (set-recs …)))` を `src/polysted/session.clj` に書き、`commands` 表に `:foo #'foo` を足す。
3. REPL の短い関数（`src/polysted/session.clj` の REPL 層）を足す。
4. TUI のキーは `src/polysted/tui.clj` の `normal-keys`（または `direct-keys`）に `[:cmd :foo 引数…]` で足し、`help-text` に説明を書く。GUI は自動で同じキーが使える。
5. README・`実装状況と仕様.md` を更新（`CLAUDE.md` の方針）。

### 5.2 新しい画面を足す
- 画面のキー処理と描画は `src/polysted/tui_screens.clj` に（`xx-key`・`render-xx`）。`src/polysted/tui.clj` の `handle-key` と `render-lines` の分岐に足す。共通のキーが要るなら引数で関数を受け取る（`ts-key` と同じ形）。
- 入力欄が要るなら、`src/polysted/tui_base.clj` の `prompt-labels` に見出しを足し、確定は `submit`（`src/polysted/tui.clj`）か画面ごとの `xx-submit`。

### 5.3 新しいファイルを足す
- `src/polysted/xxx.clj` に `(ns polysted.xxx (:require …))` で作り、使う側の `:require` に足す（読み込み順の表は無い）。
- `run-checks` を書いたら `src/polysted/check.clj` の `check-nss` に足す。README の「ファイル構成」と、この目録の 1.2 も直す。

### 5.4 副作用（ファイル・音・端末）を足す
- TUI のキー処理は純粋のまま、`(update ui :effects conj [:名前 引数])` で副作用を積み、`src/polysted/tui.clj` の `perform` に実行を書く（GUI も同じ `perform` を使う）。

### 5.5 確かめ方
- 全チェック: `clojure -M:check` で「NG 0 件」（終了コード 0）。
- 静的解析: `CLAUDE.md` の clj-kondo のコマンドで警告 0。

- 音は人の耳で（再生・録音）。
